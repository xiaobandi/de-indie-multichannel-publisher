# 规则校验 · 架构与流程图

## 本技能的四层结构

```mermaid
flowchart TB
  U["使用层：多平台发布与数据回捞助理 的使用者"]
  T["触发层：规则校验"]
  X["执行层：5 个步骤"]
  O["产出层：校验报告"]
  U --> T --> X --> O
```

| 层 | 内容 |
|---|---|
| 使用层 | 需要多平台内容分发的全体独立开发者与内容创作者；员工定位：一次录入、十平台分发、数据自动回捞的"分发中控台" |
| 触发层 | 关键词 / 显式点名「规则校验」；触发方式：用户提出需求 |
| 执行层 | **接收输入**：确认拿到的是「平台稿」，先做完整性检查。 → **校验字数/图片比例/违禁词**：按该定义执行，并把用到的输入项显式写进产出。 → **交叉校验**：把本步结论与上一步结论对一遍，出现矛盾先解决矛盾再往下走。 → **落盘产出**：按「输出契约」四要素定稿，缺数据的写 `<待填>`。 → **回指自检**：逐个数字回指输入来源，回指不上的删掉。 |
| 产出层 | 校验报告 |
